description:
Adds a compact, opinionated RAG quickstart that demonstrates multitenant isolation patterns for local development and small-scale staging. Motivation: teams building multi-tenant LLM features often need repeatable, low-friction examples showing how to keep per-tenant data, auth, and cache boundaries while using Redwood for inference. This quickstart provides a runnable TypeScript + Docker Compose sandbox and a tiny local proxy shim that routes requests to per-tenant indexes, enforces per-tenant rate limits, and demonstrates per-tenant prefix KV caching in the Redwood client. Features included: - TypeScript example service (Express) with tool-calling adapter to a document index and a sandboxed LLM route - Local proxy shim (Node) to emulate tenant routing and header-based auth for dev loops - Docker Compose to bring up Redis (per-tenant cache), a lightweight vector store (Weaviate-lite shim), and the example service - A small set of end-to-end tests (Playwright + Jest) that exercise tenant isolation and fallback behaviors - Console docs page addition with recommended security controls and checklist for production hardening - Telemetry snippets showing how to correlate token/route metrics per-tenant - Optional notes on Dedicated/Private deployment differences and how to map tenant routing into the Redwood routing policy This description contains the PR checklist, test notes, and upgrade guidance. Checklist: [x] runnable quickstart with `make up` and `make test` [x] docs page describing migration to Dedicated/private [x] sample prompts and prompt sets for regression testing [x] CI job added for the quickstart smoke test [x] license/NOTICE checked for third-party shims Breaking change: none. Backwards-compatibility: the example uses the public Redwood SDK surface and does not change any runtime API. See release_notes for user-facing changes.
