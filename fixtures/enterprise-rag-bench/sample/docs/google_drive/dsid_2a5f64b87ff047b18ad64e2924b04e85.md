Notes on table and drivers:

- Hire-Heavy assumes we absorb peak with headcount (ops + servicing) and increase reserved capacity; higher fixed costs but better margin if sustained.

Pricing sensitivity analysis (mechanics):
- Unit economics modeled at token-level: revenue_per_1k - infra_cost_per_1k - S&M/overhead_per_1k = contribution.
- Infra cost per 1k tokens (approx): base reserved = $0.14 /1k; with fractional bursts added = base + variable_burst_cost.
- Example: Lease-Heavy adds ~$0.05–0.09 /1k depending on burst utilization; translate to price moves or margin compression.

Example math (Lease-Heavy):
- Extra fractional spend: 12,000 hrs * $1.10 = $13,200 / mo -> normalized to tokens = $13,200 / 1.2B tokens * 1000 = $0.011 /1k tokens incremental.
- But operational inefficiencies + provisioning overhead -> multiplier x4 => estimated $0.044 /1k tokens (we conservatively model $0.05).

Trigger rules (operational):
- If rolling 4-week peak utilization exceeds 85% reserved throughput -> flip to Lease-Heavy (execute swapbook) for next 6 weeks.
- If sustained > 12 weeks at >70% baseline and customer growth steady -> start Hire-Heavy conversion process.
- If price elasticity signals (usage drop >8% after price change) -> pause planned commit increases and run hybrid-mode.

Risks and mitigations:
- Risk: fractional leases introduce invoice timing noise and COGS volatility. Mitigate: short-term reserve buffer in accounting and weekly reconciliation.
- Risk: contractor-to-hire conversion slows down and comp premium rises. Mitigate: offer conversion bonuses and pipeline of candidates pre-screened.
- Risk: price cuts to defend or win customers degrade unit economics if commitments don’t convert. Mitigate: trial credits tied to usage milestones and auto-rollback clauses.

TL;DR Recommendation (working):

- Prefer Hire-Heavy only when >3 months sustained lift with >70% plateau.
- Tie any price decreases to explicit conversion or commitment signals (time-limited credits rather than permanent cuts).
