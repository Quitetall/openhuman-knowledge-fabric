Purpose / quick context:
This is my personal scratchbook for the "adaptive anchor" idea — a lightweight few-shot template system that tries to harvest stable exemplars (anchors) from observed model outputs and use them as scaffolding for later prompts. Not a polished plan, just iterations, surprising failures, and small prompt drafts I want to keep around.

High-level hypothesis:
- Some domains have stable, reusable exemplars (phrases, formatting, canonical answers) that improve downstream consistency if surfaced as anchors.
- Anchors should be short, noisy-tolerant, and re-evaluated periodically (harvest -> validate -> prune).
- There is a tradeoff: adding anchors can reduce variance but may introduce bias/overfitting to historical patterns. Need light heuristics to detect drift.

Experiment matrix (quick):
- Task families: customer-support resolution steps, micro-summaries for product changelogs, policy classification (safety taxonomy).
- Models: open-llm-v1-12B-quant (local sim), hosted-redwood-std-1, dedicated-llm-2
- Variables: #anchors (0/2/5), anchor placement (prefix/inline/suffix), anchor style (examples vs. single-line canonical), allow memory caching (KV on/off).

Observed failure modes (notes):
1) Anchor Collapse: when anchors are too-prescriptive, model echoes anchors verbatim even when context requires modification. Example: anchor says "Always ask for order ID" so model attaches a request even when user already provided it.
2) Temporal Drift Hallucination: anchors harvested from old outputs carry stale facts (pricing/legal wording) and get reintroduced.
3) Anchor Interference with Instruction-following: mixing anchors with a clear instruction sometimes confuses the completion order (model tries to follow anchor formatting rather than instruction sequence).
4) Token budget regressions: adding 5 anchors (avg 18 tokens) pushes prompt length past cheap-sequence threshold -> throughput impact.

Mini-protocol for harvesting anchors (rudimentary):
- Harvest candidates from high-quality completions only: success label = downstream metric pass (e.g., resolution recorded, safety classifier OK) AND no operator edit.
- Score candidates by: frequency (how often same phrasing occurs), compactness (prefer shorter), contextual-robustness (survives when we shuffle shots).
- Maintain bucket: accepted / probation / pruned. Probation candidates get validated on a fresh window of interactions.

Prompt drafts (rough)
1) Support resolution template (prefix anchors, 2-shot):
System: "You are a concise support assistant. Use bullet steps and always confirm when resolution actions are complete."
Anchor lines:
- "Always confirm the customer's account ID and last four digits of order."
- "Offer the option to escalate or schedule a follow-up."
Shots:
Q1: "My app crashed after update. It says X. I tried reopening." -> A1: "Ask environment + logs -> clear cache -> update -> escalate if persists."
Q2: "I can't login, says wrong password." -> A2: "Confirm username, ask if tried reset link, offer device check."
Instruction: "Given the conversation, produce 3-step resolution and a suggested next message."
Notes: with anchors present model tended to append confirmation even when Q included account ID. Try moving anchors to suffix in next run.

2) Micro-summary (inline anchor style):
System: "Summarize changelog entry into a single-line headline and 2 bullets. Prefer active voice."
Anchor: "Headline must start with verb; no version numbers."
Shot examples (few-shot):
- Input: "v2.1: fixed crash on sign-in when cookie expired" -> Output: "Fix sign-in crash" + bullets
- Input: "Add dark mode toggle and keyboard shortcut" -> Output: "Introduce dark mode" + bullets
Experiment: when anchor is inline (embedded before examples), headline quality improves but risk of truncation increases for long inputs.

3) Safety taxonomy classifier (anchors as exemplars):
System: "Classify the user message into safety categories: harassment, sexual, violent, illicit, none. Return single label."
Anchors (2 exemplars each):
- harassment: "You idiot, leave me alone" -> harassment
- sexual: "Describe explicit sexual acts" -> sexual
- violent: "I'm going to hurt you" -> violent
Problem: model sometimes overfits to exemplar wording and misses paraphrases. Need paraphrase-augmented anchors.

Failure case notes + quick triage attempts:
- Overfitting -> solution trial: paraphrase-expand anchors (3 variants per exemplar) + temperature lowering. Early signal: lower diversity but improves recall on paraphs.
- Stale facts -> solution trial: anchor TTL = 14 days, auto-evaluate on rolling sample. Cheap but reduces usefulness for low-volume categories.
- Token budget -> solution trial: compress anchors by heuristics (drop stopwords; use shell-like shorthand). Observed tiny improvement in throughput but slight quality dip.

Open ideas / experiments to run next:
- Active pruning heuristic: if anchor increases operator edits in last 2 weeks, automatically move to probation.
- Anchor alignment test: run paraphrase probe set (50 examples) to measure generalization; keep anchors that maintain F1 > .7.
- Dynamic anchor placement: let router choose prefix vs suffix based on sequence length and model latency SLO.
- Anchor-conditional memory: store anchors at route-level not request-level; interleave cache hits only when similarity > threshold.
