ben_sdk: probable root cause: our package.json exports map has both import/require targets but relative paths in the published tarball changed in 0.7.2 (we moved files under `lib/` in the bundle but exports still point to `dist/`). Next resolves to the ESM path and Next's webpack config is including the module in the lambda bundle. That can cause process.env keys to be inlined or lost depending on how code uses `process.env` vs runtime reading.

mike_eng: short-term workarounds:
- pin to 0.7.0: `npm i redwood-inference@0.7.0` (we reverted a packaging change there)
- clean lockfile + node_modules, then rebuild: `rm -rf node_modules package-lock.json && npm i`
- set `skipLibCheck: true` in tsconfig to ignore duplicate type declarations while we patch
- ensure your API key is read at runtime (e.g., `const client = new RedwoodClient(process.env.REDWOOD_API_KEY!)` inside handler, not top-level module initialization)

alice_devex: additional workaround for Next: add `webpack: (config) => { config.externals = config.externals || []; config.externals.push(/redwood-inference/); return config; }` in next.config.js so SDK isn't bundled into edge lambda.
