# KF-WAR-0001 deliverable 7: the controls no automated check covers

Work order deliverable 7 and obligation OBL-006 ask for "an enumeration of every control no
automated check covers, written down rather than left to be discovered", each entry naming why no
automated check can cover it. This is that list, written on 2026-10-07 after the first rehearsal
of the ADR 0039 install on a Debian 13 KVM guest shaped like the VPS (the rehearsal record is
[rehearsal-2026-10-07.md](rehearsal-2026-10-07.md)).

**This file is not commissioning evidence.** KF-WAR-0001 is a draft; nothing here is recorded
against it, and nothing here was observed on the VPS. Each entry is a control the VPS's
commissioning must evidence by a person's act, with the reason a program cannot.

"Automated check" means `kf-commissioning` (`gate://kf.host.commissioning@1.0.0`), `kf-readiness`
and its timer-liveness pre-check, `provision-host.sh --check`, the restore drill and the release
verifier. The gate's own `known_blind_spots`
([`docs/gates/kf.host.commissioning@1.0.0.yaml`](../../../gates/kf.host.commissioning@1.0.0.yaml))
are entries 1 to 4; the rest were found by the rehearsal or by reading what each check reads.

| 1   | The host is independent hardware, not a VM on the workstation that built the release                                                                     | Every check reads the host it runs on; a VM on the builder presents the same states (gate blind spot 1). ## What changed in the automated coverage because of the rehearsal

Two controls that were listed as needing a person no longer do, because the rehearsal made the
machine do them: every database login and its connection string on a host whose PostgreSQL is
local, and the off-site copier's ssh identity. Both are `provision-host.sh` now, and
`tests/deployment/provision-host.test.ts` holds them.
